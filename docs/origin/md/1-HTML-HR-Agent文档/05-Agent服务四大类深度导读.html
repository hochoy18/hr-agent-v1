1.1 继承与 MRO：物理拆分，不是逻辑分层

接线只有两处——agent_service.py:32-34 的三行 import，和 agent_service.py:67 的类声明：

class AgentService(
    _AgentServiceCoreMixin,        # 父类 1（core.py）
    _AgentServiceEditingMixin,     # 父类 2（editing.py）
    _AgentServiceResourcesMixin,   # 父类 3（resources.py）
):
  • 三个 mixin 没有 __init__、不独立实例化。它们的方法直接用 self.db、self.tool_registry、self.llm_service——这些属性全部由宿主 AgentService.__init__（agent_service.py:74）提供。
  • 方法查找顺序（MRO）：AgentService 本类 → Core → Editing → Resources。本文件里每一个搜不到 def 的 self._xxx() 调用，都来自 mixin。
  • mixin 之间互相交叉调用：editing 调 resources 的 _recent_generated_resources / _match_delete_resources；resources 调 core 的 _stream_text；core 调 resources 的 _parse_requirements / _generate_jd。所以不能把它们理解为依赖分层，宿主类才是完整实体。
⚠️ 拆分痕迹：不要被 import 误导 editing.py 头部 import 了 DifyService、ExamService、hashlib 等大量它根本用不到的模块——这是从原单文件机械切割时留下的。editing 实际只用 LLMService，不调 Dify。

2.1 chat()：LangGraph 兼容门面 agent_service.py:101

    return await _get_graph_service().run_chat(agent_service=self, ...)
  • 编排逻辑已迁移到 LangGraph（app/agent/graph.py），chat() 只保留原签名做兼容门面，供评测脚本 agent_eval_runner 进程内调用。
