# 需求文档

## 1. 文档目的

本文档说明 HR Agent 项目要做什么、不做什么、用户需要什么、业务流程如何闭环、功能边界在哪里。文档面向产品、研发、测试、业务负责人和上线验收人员。

## 2. 需求范围

### 2.1 范围内

- 用户注册、登录、个人信息、JWT 鉴权。
- 用户管理、角色管理、超级管理员权限控制。
- HR Agent 对话入口、意图识别、受控工具编排、SSE 流式响应、多轮指代与按描述删除资源。
- JD 生成、保存、查询、修改、删除。
- 简历评分标准生成、保存、查询、修改、删除。
- 简历上传、解析、AI 评分、历史记录、状态更新、删除、导出。
- 面试方案生成、保存、查询、修改、删除。
- 智能面试：腾讯会议建会/取消/状态同步、音视频或文档上传、腾讯会议录制转写、逐字稿分段与问答配对、四维评分、评价修订与留痕。
- 文档上传、处理、查询、删除、文档切片查看。
- 知识库管理、知识助手问答、知识库自动选择。
- 试卷生成、试卷管理、考试分享、考试提交、考试结果查看和导出。
- 邮箱配置、连接测试、邮件抓取、日志查看。
- 工作台统计、招聘趋势、培训完成情况、近期活动。

### 2.2 范围外

- 招聘渠道发布与渠道效果分析。
- 候选人 CRM、Offer 审批、背调、入职办理。
- 企业组织架构、绩效、薪酬、考勤等完整 HRIS 功能。
- 自动录用、自动淘汰、自动发送不可撤销通知。
- 视频面试自研音视频能力：会议能力由腾讯会议提供，本项目不实现自有会议服务。
- 面向候选人的完整招聘门户。
- 企业级监控、CI/CD、服务发现、灰度平台建设。
- 大规模多租户 SaaS 计费、套餐、租户隔离和商业化运营后台。

## 3. 用户角色与权限需求

| 角色 | 核心诉求 | 主要权限 |
| --- | --- | --- |
| 超级管理员 | 管理系统、用户、角色、邮箱配置 | 用户管理、角色管理、邮箱配置、全部业务数据维护 |
| HR 负责人 | 查看招聘培训进展，保证流程质量 | 查看统计、招聘结果、培训结果、关键业务数据 |
| HR 专员 | 执行招聘任务 | JD、评分标准、简历筛选、面试方案、面试评价与修订、邮件草稿 |
| 培训管理员 | 生成和管理考试 | 文档上传、试卷生成、考试管理、结果查看 |
| 普通员工 | 查询知识或参与考试 | 知识问答、考试分享页面 |
| 候选人/考试参与者 | 完成考试或测评 | 通过分享链接访问考试页面 |

权限要求：

- 登录后才能访问主系统页面。
- 用户管理、角色管理、邮箱配置等敏感操作仅允许超级管理员访问。
- 普通业务功能至少要求已认证用户。
- 考试分享页面可按业务需要允许免登录访问。
- 后端接口必须以 JWT 和角色校验为准，前端菜单隐藏不能作为唯一权限控制。

## 4. 核心用户需求

### 4.1 HR 专员

- 我希望输入岗位需求后自动生成结构完整的 JD，以减少重复撰写。
- 我希望系统同步生成评分标准，使后续简历筛选口径一致。
- 我希望批量上传简历并自动评分，快速定位高匹配候选人。
- 我希望看到评分理由和维度，而不是只有一个总分。
- 我希望基于候选人和岗位自动生成面试方案，便于面试官使用。
- 我希望面试的会议、录像、逐字稿和评分留在同一条记录里，事后能复盘候选人到底说了什么。
- 我希望面试评分能指出「哪一问、哪一句」，而不是只给一个总分。
- 我希望评分不符合我的判断时可以修订，并留下修订痕迹。
- 我希望通过 Agent 直接描述任务，由系统判断去哪个功能或执行哪个流程。

### 4.2 HR 负责人

- 我希望看到招聘相关统计，了解当前 JD、简历筛选、面试等进展。
- 我希望流程产物可追踪、可复用、可删除。
- 我希望 AI 结果保留人工确认空间，避免系统替 HR 做最终判断。

### 4.3 培训管理员

- 我希望上传培训文档后，系统可以自动生成试卷。
- 我希望配置题型、难度、题量、分值等信息。
- 我希望发布考试链接并查看考试结果。

### 4.4 系统管理员

- 我希望能管理用户、角色和邮箱配置。
- 我希望系统有健康检查、错误提示和日志，便于定位问题。
- 我希望敏感配置不被普通用户访问。

## 5. 业务流程需求

### 5.1 招聘主流程

1. HR 输入岗位需求。
2. 系统解析岗位名称、地点、薪资、经验、学历、技能要求等信息。
3. 系统调用 JD 生成能力输出 JD 初稿。
4. 系统生成与 JD 匹配的评分标准。
5. HR 保存或编辑 JD 与评分标准。
6. HR 上传候选人简历。
7. 系统解析简历，结合 JD 和评分标准输出评分、匹配度和理由。
8. HR 查看候选人排序和评分详情。
9. HR 选择候选人生成面试方案。
10. HR 为候选人发起腾讯会议面试。
11. 会中/会后上传音视频或腾讯会议录制转写，系统转写并配对问答。
12. 系统输出四维评分与证据，HR 复核、修订并确认结论。
13. HR 根据结论安排后续沟通或准备邮件通知。

### 5.2 Agent 对话流程

1. 用户在 HR Agent 输入自然语言，可附带附件（简历、文档）。
2. 前端调用 Agent 流式接口，后端在 LangGraph 主图入口写入本轮消息。
3. `route_intent` 节点构建对话记忆（含历史产物），再跑「规则快通道 + 受控 ReAct 决策」，得到 intent 与目标节点。
4. 条件边按 intent 分发到对应意图子图：JD 生成、JD 修改、评分标准修改、简历筛选、面试方案、试卷生成、资源删除、邮件草稿、普通对话。
5. 需要用户确认的意图会在子图内 `interrupt` 真暂停，把确认载荷通过 SSE `interrupt` 事件推给前端，前端渲染确认卡片。
6. 用户确认后恢复图执行，子图继续跑执行节点，产物写回 checkpoint 的 `artifacts`。
7. 若缺少前置条件，节点返回缺失字段、建议和对应页面入口，不直接失败。
8. 前端按 SSE 事件渲染步骤、流式文本、产物和下一步建议；`final` 事件结束本轮。
9. 下一轮用户说「刚才那个」时，路由与编辑/删除链路优先从 checkpoint 中的 `artifacts` 反查，无需用户重复描述。

### 5.3 知识库问答流程

1. 用户上传文档。
2. 系统保存文件并处理文本内容。
3. 系统将文档切片并向量化，写入 PostgreSQL + pgvector。
4. 用户在知识助手输入问题。
5. 系统进行知识库选择、查询增强、向量召回、文本匹配和 rerank。
6. 系统按最低相似度阈值过滤召回结果；全部低于阈值时按「资料不足」处理。
7. 系统将相关上下文交给 LLM 生成回答。
8. 用户查看回答和来源上下文。

### 5.4 培训考试流程

1. 培训管理员在试卷生成页选择已有知识库中的文档作为出题依据（也可在 Agent 对话中直接上传参考附件）。
2. 管理员输入试卷配置或通过 Agent 表达考试需求。
3. 系统解析考试意图，生成试卷。
4. 管理员保存试卷并生成分享链接。
5. 考试参与者通过链接答题并提交。
6. 系统记录考试结果，支持查看和导出。

### 5.5 系统管理流程

1. 超级管理员登录系统。
2. 管理用户信息、角色和权限。
3. 配置邮箱服务并进行连接测试。
4. 查看邮件抓取日志和最近邮件。
5. 通过健康检查和日志确认系统状态。

### 5.6 面试评价流程

1. HR 在智能面试页选择一位已评分候选人，补充会议主题与时间，点【开始面试】。
2. 系统调用腾讯会议 MCP 创建会议，回写会议号、入会链接、密码和会议状态。
3. 面试结束后，HR 从三种材料中择一提供：本地上传音视频、上传文档（逐字稿/纪要）、直接拉取腾讯会议录制转写。
4. 系统先确认候选人姓名（说话人可能未标注），再执行转写。
5. 转写完成后，系统对逐字稿做分段与说话人识别，配对出「一问一答」列表。
6. 系统对每组问答判定「是否回应问题」「信息量档位」「追问深度」，命中的确定性规则直接覆盖模型结论。
7. 系统按可核对维度推导分数，再让模型对其余维度打分，加权得到总分，并生成风险提示。
8. 若触发「结论待定」条件，系统不给出录用建议，只给出待定原因。
9. HR 可对维度分数或总分做人工修订，修订需记录原值、新值、修订人和时间。
10. 评价结果与逐字稿随面试记录保存，可在面试记录 Tab 回看。

## 6. 功能需求

### 6.1 认证与用户管理

- 支持用户注册、登录、刷新 Token、获取当前用户。
- 支持用户列表、详情、更新、删除。
- 支持管理员创建用户、分配角色、创建角色、删除角色。
- 支持超级管理员角色校验。
- 登录失败、Token 过期、无权限时返回明确错误。

详细规则：

- 注册时用户名、邮箱应唯一。
- 登录成功后返回访问令牌和令牌类型。
- Token 失效后前端应引导用户重新登录。
- 普通用户不得调用用户列表、角色管理、邮箱管理等管理员接口。
- 超级管理员角色以系统内角色或 `is_superuser` 校验为准，不能只依赖前端菜单控制。

### 6.2 HR Agent

- 支持普通对话接口和流式对话接口。
- 支持附件元数据传入（简历、文档，单轮最多 20 份）。
- 支持以下意图：`jd`（生成 JD + 评分标准）、`jd_edit`（修改 JD）、`criteria_edit`（修改评分标准）、`resume_screening`（简历批量评分）、`interview_plan`（面试方案）、`exam_generate`（试卷生成）、`resource_delete`（按描述删除资源）、`email_notification`（邮件草稿，来自技能包）、`general`（普通对话）。
- 支持根据前置条件返回缺失信息。
- 支持输出步骤、产物、建议、路由和执行状态。
- 邮件类动作只能生成草稿或进入确认流程，不允许未经确认自动发送。
- 支持多轮指代：用户说「刚才那份 JD」「上一个候选人」时，能从本轮上下文或历史产物中定位对象。

详细规则：

- **决策来源**：路由优先走规则快通道（关键词），未命中再走受控 ReAct 决策；决策输出 `mode`、`action`、`intent`、`thought`、`observation`、`confidence`、`reply`，其中 `mode` 与 `action` 必须自洽。
- **保守优先**：不确定时选择普通对话，避免误触发写操作；删除类请求只有在观察到明确目标时才允许进入删除链路，不允许臆造名称或 ID。
- **流程约束**：确认节点是图上的真暂停（`interrupt`），不是提示词里的一句「请确认」。用户确认前不会执行写操作。
- **写操作留痕**：JD、评分标准、面试方案、试卷、简历评分记录、邮件草稿的生成与修改都应落到可查询的对象上；删除应返回删除对象的名称与数量。
- **产物累积**：跨轮产物保存在图状态中（上限 50 条），编辑/删除链路优先图状态反查，其次回退到会话消息中的历史响应。
- **返回结构**：`message`、`intent`、`route`、`steps`、`artifacts`、`suggestions`、`requires_confirmation`、`missing_fields`。
- **流式事件契约**：`progress`（节点/步骤进度）、`delta`（文本增量，带 `section`）、`artifact`（产物就绪）、`interrupt`（等待确认，含 `thread_id` 与 `payload`）、`final`（本轮终态，每轮有且仅有一个）、`error`。
- **附件直通**：`/agent/resume-screen/stream`、`/agent/interview-plan/stream`、`/agent/exam/stream`、`/agent/exam/document-stream` 等端点带预设意图，跳过路由决策直达对应执行节点。

### 6.3 JD 与评分标准

- 支持根据岗位需求生成 JD。
- 支持保存、查询、更新、删除 JD。
- 支持生成并保存评分标准。
- 支持按岗位、状态或关键字查询历史记录。
- 支持 JD 与评分标准作为后续简历评分输入。

详细规则：

- JD 必填字段至少包括标题和正文内容。
- 可选字段包括部门、地点、薪资范围、经验、学历、岗位类型、技能列表、状态、元数据。
- JD 默认状态为草稿，业务可根据需要扩展为已发布、归档等状态。
- 评分标准默认总分为 100 分。
- 评分标准应支持维度化存储，包括维度名称、权重、满分和评分说明。
- 删除 JD 前应确认是否存在关联评分标准或简历评估记录；如果当前实现未做强约束，验收时需确认业务可接受。

### 6.4 简历筛选

- 支持 PDF、DOC、DOCX、TXT、MD 等简历格式。
- 支持上传文件大小限制（默认 10MB）。
- 支持自动解析简历内容。
- 支持结合 JD 或评分标准进行匹配评分。
- 支持查看评分结果、评分指标、AI 建议和历史记录。
- 支持状态更新、删除和压缩包导出。

详细规则：

- 简历评估必须关联一个 JD。
- 评分标准可选；若未选择，系统可使用 JD 内容或默认评估逻辑。
- 评估结果至少包括候选人姓名、应聘岗位、工作年限、教育背景、总分、评分维度和评分理由。
- 支持候选人状态更新，状态枚举应在产品验收时固定。
- 同一候选人重复上传的处理规则需在上线前确认：允许重复、覆盖旧记录或提示用户选择。
- AI 评分结果不作为淘汰或录用的最终依据。

### 6.5 面试方案

- 支持基于候选人简历、JD 和评分结果生成面试方案。
- 支持保存、查询、更新、删除面试方案。
- 面试方案应包含面试重点、问题建议、考察维度、评分建议。

详细规则：

- 面试方案必须关联一条简历评估记录。
- 创建时必须包含候选人姓名、候选人岗位和方案正文。
- 方案内容应覆盖技术能力、项目经验、岗位匹配度、风险点和追问建议。
- 面试方案保存后允许 HR 编辑，不要求完全采用 AI 原文。

### 6.5.1 智能面试（会议 + 转写 + 评价）

功能范围：

- 支持为候选人发起腾讯会议（主题、起止时间、时区、等候室开关），回写会议号、入会链接、密码。
- 支持查询会议状态、手动同步状态、取消会议。
- 支持三种材料来源：本地上传音视频、上传文档（逐字稿/纪要）、拉取腾讯会议录制转写。
- 支持在分析前修正候选人姓名，并记录该项修正。
- 支持展示录制设置检查结果（如会议是否开启云录制）。
- 支持逐字稿分段、说话人识别、问答配对、四维评分、风险提示与结论。
- 支持人工修订评分并留痕。

详细规则：

- 一场面试（`interviews` 一条记录）必须关联一位候选人的简历评估记录。
- 会议时间采用 ISO 8601 且保留时区；结束时间必须晚于开始时间。
- 未配置腾讯会议 Token 时，建会应返回明确错误（503 提示未配置），而不是静默失败。
- 上传音视频单文件大小受 `INTERVIEW_MEDIA_MAX_MB` 限制（默认 500MB）；服务端转写依赖 `ffmpeg`。
- 分析前必须确认候选人姓名；未确认时分析入口应置灰或先弹出确认。
- 评分维度固定为四项，权重：问答一致性 35%、事实信息量 35%、逻辑条理性 15%、表达组织能力 15%。
- 问答一致性与事实信息量由规则从「是否回应问题」「信息量档位」推导；逻辑条理性与表达组织能力由模型按 rubric 打分。
- 每个维度必须能指回逐字稿中的具体问答；不允许只给分数不给依据。
- 追问深度不作为候选人得分维度，作为「面试执行度」单独呈现，用于评价面试官是否深挖。
- 出现以下任一情况时，结论必须为「待定」，不得给出录用/不录用建议：有效问答样本不足、候选人说话人无法确认、关键维度无法评分、评价文本与逐字稿明显不符。
- 人工修订只允许 HR 在评价结果页操作，修订必须记录修订人、时间、原值和新值；修订后总分重新计算并标记为「已人工修订」。
- 转写与分析状态必须可观测：`not_started`、`transcribing`、`transcript_ready`、`analyzing`、`completed`、`failed`，失败原因写入记录。

### 6.6 知识库与知识助手

- 支持文档上传、处理、切片和删除。
- 支持知识库集合创建、更新、删除。
- 支持知识库问答、自动选择知识库。
- 支持查询增强、向量召回、文本匹配、rerank。
- 对解析失败、空文档、无相关结果应返回明确提示。

详细规则：

- 知识库名称必填，支持描述、公开状态、可搜索状态、分类、标签和元数据。
- 文档上传可绑定知识库，也可以作为未归类文档保存。
- 文档处理后应保存提取文本、文件哈希、文件大小、MIME 类型和切片信息。
- 知识问答应优先基于知识库内容回答；无相关内容时应提示不确定。
- 用户删除文档时，应同步考虑文档切片和向量数据清理。

### 6.7 试卷与考试

- 支持基于文档生成试卷。
- 支持配置题型、难度、题量、分值。
- 支持试卷列表、详情、更新、删除。
- 支持考试分享链接。
- 支持提交答案、记录考试结果、查看和导出结果。

详细规则：

- 试卷生成请求应包括标题、科目、总分，可选难度、时长、题型、题量、知识文件和特殊要求。
- 试卷保存后应支持列表、详情、更新、删除。
- 考试提交应记录考试 ID、学生姓名、部门、答案和试卷内容。
- 分享链接是否免登录访问，应由业务验收确认。
- 若试卷已被提交答题，是否允许修改或删除，需在上线前明确。

### 6.8 邮箱配置

- 支持邮箱配置新增、查询、更新、删除。
- 支持连接测试。
- 支持手动抓取邮件、查看抓取日志和最近邮件。
- 邮箱配置仅允许超级管理员操作。

### 6.9 统计看板

- 支持工作台概览。
- 支持招聘趋势、培训完成情况和近期活动查询。

## 7. 非功能需求

### 7.1 性能

- 常规列表查询应在可接受时间内返回，避免前端长时间空白。
- LLM 生成类任务应优先使用流式响应或进度提示。
- 文档上传和简历上传应限制文件大小，当前配置默认最大 10MB。

建议指标：

- 普通列表查询：试点环境下 3 秒内返回。
- 登录和权限校验：试点环境下 2 秒内返回。
- 长文本生成：5 秒内出现首个进度或流式片段。
- 文件上传：应显示上传进度或处理状态。
- 面试转写：45 分钟音视频在试点环境下 10 分钟内完成转写，转写期间前端应显示进度且可离开页面。
- 面试分析：转写就绪后 3 分钟内产出评分结果。

### 7.2 安全

- 密码必须哈希存储。
- API 使用 JWT Bearer Token 鉴权。
- 生产环境必须替换默认 `SECRET_KEY`、数据库密码和外部 API Key。
- 上传文件应限制格式和大小。
- 邮箱、Dify、LLM、腾讯会议 Token 等敏感配置不得暴露给普通用户；腾讯会议 Token 等同于账号身份，不得下发到前端。
- 面试音视频与逐字稿属于敏感数据，访问需登录且只能访问自己创建的面试记录。

### 7.3 可用性

- 前端菜单应按业务模块组织。
- 表单错误、权限错误、上传失败、生成失败应有明确提示。
- 长任务要有进度反馈。

### 7.4 可维护性

- 后端按 endpoint、schema、model、service 分层。
- 前端 API 请求统一维护在 `src/api`。
- 新增业务功能应补充接口、服务、页面和测试用例。

### 7.5 合规与人工确认

- AI 输出只能作为辅助建议，不作为最终录用、淘汰或评价决定。
- 关键通知和候选人沟通内容应由 HR 审核确认。
- 简历和候选人信息属于敏感个人信息，上线前需确认存储、访问和删除策略。

### 7.6 可观测性

- 后端应记录启动、数据库初始化、外部服务调用失败、权限失败、文件解析失败等关键日志。
- 上线环境应具备日志查询方式。
- 企业生产化阶段建议补充集中日志、告警和调用链追踪。

### 7.7 可恢复性

- 数据库需要定期备份。
- 上传目录需要持久化和备份。
- 上线前应保存旧版本前端资源和后端包或镜像。
- 发生严重故障时应可回滚到上一版本。

## 8. 功能边界与优先级

| --- | --- | --- |

| P0 | 智能面试：建会、转写、配对、评分、修订 | 面试过程可留痕、评价可复核 |

| P0 | 试卷生成、考试管理、结果查看 | 培训考试可闭环 |
| P1 | HR Agent 对话编排与流式响应 | 自然语言可触发或引导业务流程 |
| P1 | 邮箱配置和邮件 Skill | 管理员可配置，通知需确认 |
| P1 | 统计看板 | 管理者可查看运营概览 |
