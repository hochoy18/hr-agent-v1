# 权限矩阵与数据字典

## 1. 文档目的

本文档用于明确 HR Agent 项目的角色权限、核心数据对象、字段含义、枚举值和数据治理规则。研发、测试和业务验收应以本文档作为权限与数据口径依据。

## 2. 角色定义

| 角色 | 说明 |
| --- | --- |
| 超级管理员 | 管理用户、角色、邮箱配置和系统级资源 |
| HR 负责人 | 查看招聘、候选人、面试和统计数据 |
| HR 专员 | 执行招聘流程，包括 JD、简历、面试 |
| 培训管理员 | 管理培训资料、试卷和考试结果 |
| 普通员工 | 使用知识问答或参与考试 |
| 候选人/考试参与者 | 通过分享链接参与考试，不进入后台系统 |

说明：

- 最终权限以后端接口校验为准，前端菜单隐藏只是体验优化。
- 当前实现中，用户管理、角色管理、邮箱配置接口均要求 `is_superuser`；普通用户即使直接访问路由也会被前端守卫拦回工作台，后端仍会独立校验。
- 业务接口按「登录用户 + 本人数据」隔离：列表类接口按 `user_id` 过滤，详情/更新/删除接口校验归属，跨用户访问返回 404/403。

### 3.2 可选扩展权限

如试点企业希望扩大使用范围，可在需求变更评审后开启以下扩展权限：

| 扩展项 | 可开放角色 | 风险 |
| --- | --- | --- |
| 培训管理员触发招聘 Agent 工具 | 培训管理员 | 可能误操作招聘数据 |
| HR 负责人管理知识库 | HR 负责人 | 可能修改企业知识资料 |
| HR 专员管理知识库 | HR 专员 | 可能上传不合规资料 |
| HR 负责人查看考试结果 | HR 负责人 | 可能扩大培训结果可见范围 |
| 普通员工查看统计看板 | 普通员工 | 可能暴露业务运营数据 |

扩展权限必须记录开启原因、影响范围、审批人和回退方式。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| id | UUID | 是 | JD ID（远程生成） |
| title | string | 是 | 岗位标题 |
| department | string | 否 | 部门 |
| location | string | 否 | 工作地点 |
| salary_range | string | 否 | 薪资范围 |
| experience_level | string | 否 | 经验要求 |
| education | string | 否 | 学历要求 |
| job_type | string | 否 | 岗位类型 |
| skills | string[] | 否 | 技能列表 |
| content | string | 是 | JD 正文 |
| requirements | string | 否 | 原始需求 |
| status | string | 否 | 状态，默认 draft |
| meta_data | object | 否 | 元数据 |
| conversation_id | string | 否 | 关联对话 |
| workflow_type | string | 否 | 工作流类型 |

- `draft`：草稿

### 4.15 面试评价结果结构（`interviews.evaluation`）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| total_score | float | 0-100，仅由 4 个应答质量维度加权折算 |
| score_basis | string | 计分口径说明（哪些维度推导、哪些模型打分） |
| dimensions | object[] | 四维评分子项，见下表 |
| qa_pairs | object[] | 问答配对列表，每项含问题、回答、verdict、substance、followup |
| risk_signals | object[] | 风险信号（如经历断档、职责与年限不匹配） |
| execution | object | 面试执行度（追问深度统计），不计入候选人得分 |
| summary | string | 总体结论文字 |
| strengths / risks | string[] | 优势与风险要点 |
| recommendation | string | `推荐` / `待定` / `不推荐` |
| confidence | string | `高` / `中` / `低` |
| insufficient | boolean | 是否因证据不足而待定 |
| insufficient_reasons | string[] | 待定原因 |
| notes | string[] | 复核提示（说话人推断、标签缺失、转写过短等） |
| rule_version | string | 评分规则文件版本，用于结果可追溯 |

`dimensions` 子项字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| name | string | 维度名称：问答一致性 / 事实信息量 / 逻辑条理性 / 表达组织能力 |
| score | float | 得分 |
| max | float | 满分 |
| status | string | `scored` / `unscored`（不可评时不计入加权） |
| weight | float | 权重（0.35 / 0.35 / 0.15 / 0.15） |
| reason | string | 评分理由 |
| evidence | string | 引用逐字稿原文作为依据 |
| source | string | `rule`（规则推导）/ `llm`（模型打分） |

### 4.16 Agent 图状态与确认载荷

| 字段 | 位置 | 说明 |
| --- | --- | --- |
| thread_id | SSE 事件 / 请求 | 会话线程 ID，等于 `conversation_id`，用于恢复 interrupt |
| artifacts | 图状态 checkpoint | 跨轮产物，上限 50 条，编辑/删除的反查来源 |
| intent / dest_node | 图状态 | 路由结果与目标节点 |
| interrupt.payload | SSE `interrupt` 事件 | 确认卡片数据：待确认对象、字段、可编辑内容 |
| final.response | SSE `final` 事件 | 本轮完整 `AgentChatResponse`，每轮唯一 |

## 5. 数据治理要求

| 数据类型 | 敏感等级 | 管理要求 |
| --- | --- | --- |
| 用户账号和密码 | 高 | 密码哈希存储，账号权限控制 |
| 简历和候选人信息 | 高 | 限制访问、明确保留期限、支持删除 |
| 面试音视频与逐字稿 | 极高 | 录音需告知；按人隔离访问；明确保存期限；删除时同步清理文件 |
| 面试评价结果与修订记录 | 高 | 仅授权 HR/管理者访问；修订留痕不可静默覆盖 |
| 面试方案和评分结果 | 高 | 仅授权 HR/管理者访问 |
| 企业文档和知识库 | 中到高 | 按文档敏感度控制访问 |
| 试卷和考试结果 | 中 | 控制查看和导出权限 |
| 邮箱配置 | 高 | 仅超级管理员访问，不暴露密码 |
| AI 对话记录 | 中 | 避免写入不必要敏感信息 |

## 6. 数据保留建议

| 数据 | 建议保留策略 |
| --- | --- |
| 简历文件 | 试点期按业务要求保留，结束后清理或归档 |
| 简历评分记录 | 与招聘岗位周期一致 |
| JD 和评分标准 | 可长期保留用于复用 |
| 面试方案 | 与候选人流程周期一致 |
| 面试音视频文件 | 建议满足复核需求后清理（如 3~6 个月），需书面确认 |
| 面试逐字稿与评价 | 与候选人流程周期一致，评价需保留规则版本号 |
| 知识库文档 | 按企业知识管理规则保留 |
| 考试结果 | 按培训合规要求保留 |
| 日志 | 至少保留一个排障周期，生产按企业规范 |
