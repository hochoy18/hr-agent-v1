HR Agent 执行流程

基于当前代码（LangGraph 编排 + 智能面试评价），与《方案设计文档》4.5.2 / 4.5.11 / 第 5 章一致
图 1 总览 · 图 2 路由决策 · 图 3~6 意图子图 · 图 7 文件流直通 · 图 8~9 时序 · 图 10~11 智能面试
读图前先记住三个约定：
1. 主图只做路由：START → route_intent →（条件边）→ 意图子图 → END。写操作（删除、发送、落库）只发生在确定性子图里，路由模型不持有写工具。
2. 状态分两类：artifacts 用 add_artifacts reducer 跨轮累积（保留最近 50 条），steps 每轮被覆盖；db / user_id / thread_id / files 一律走 RunnableConfig["configurable"]，不进 checkpoint。
3. 确认是真暂停：interrupt() 挂起图，恢复靠 POST /agent/graph/resume + Command(resume=value)，不是靠提示词让模型「记得停下来」。

八、确认与恢复时序（interrupt → resume）

sequenceDiagram participant C as 前端 HRAgent participant E as agent_graph.py participant G as GraphService participant K as Checkpointer participant N as jd_confirm 节点 C->>E: POST /agent/graph/chat {message, thread_id} E->>G: run_stream(thread_id = conversation_id) G->>K: astream 写入本轮 state G-->>C: SSE progress {node:"route_intent", steps} G-->>C: SSE progress {node:"jd_prepare", steps} G->>N: 进入 jd_confirm N->>N: interrupt(payload) 挂起 G->>K: aget_state 取 jd_interrupt_payload G-->>C: SSE interrupt {thread_id, payload{artifacts, missing_fields}} G-->>C: SSE final {requires_confirmation:true} Note over C: 渲染需求卡片 +「确认生成」按钮 C->>E: POST /agent/graph/resume {thread_id, value} E->>G: run_stream(resume_value = value) G->>K: Command(resume=value) 恢复 N-->>G: interrupt 返回 value，继续执行 G-->>C: SSE progress {node:"jd_execute", steps} G-->>C: SSE final {artifacts:[JD, 评分标准]} G-->>C: data: [DONE]
thread_id 就是 conversation_id：同一会话的 checkpoint 连续，所以「上一轮那个 JD」能被下一轮的编辑/删除链路反查到。
